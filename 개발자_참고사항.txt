================================================================
  월드컵 예측 리더보드 — 개발자 참고사항
================================================================
  대상: 이 코드를 유지보수하거나 수정할 사람
  내용: 개발 과정에서 직접 부딪히고 검증한 것들 위주로 정리


[ 1 ] 전체 구조
───────────────────────────────────────────────────────────────
· app.py 단일 파일 Streamlit 앱. DB 없음 — 전부 평문 파일.
  - matches.json   : 경기 목록 (id, team1, team2, group)
  - results.json   : 실제 경기 결과 (team1_score, team2_score)
  - submissions/   : 팀별 폴더 + 타임스탬프 CSV (제출 기록 누적)
  - group_stage_result.json : 조별리그 순위 계산용 (matches.json과 별개 소스)

· 탭은 2개만 — 🏆 리더보드 / 📤 CSV 업로드
  조별리그 순위는 탭이 아니라 채점 기준 바로 다음의 페이지 콘텐츠.
  (탭으로 넣으면 그 탭을 선택해야만 보이므로, 항상 보이게 하려고 이렇게 뺐음)


[ 2 ] 데이터 갱신 — build_data.py
───────────────────────────────────────────────────────────────
· true_result.json(football-data.org 포맷)을 읽어
  matches.json + results.json을 재생성하는 스크립트.
· 실제 경기 결과가 갱신되면(새 true_result.json을 받으면)
  이 스크립트만 다시 실행하면 끝:

      python3 build_data.py

· FINISHED 상태인 경기만 results.json에 기록됨.
  아직 안 끝난 경기는 자동으로 채점에서 제외됨(score_df에서
  match_id가 results에 없으면 그냥 skip).


[ 3 ] CSV 제출 스키마 — 매치 ID 없음, 팀 이름으로 매칭
───────────────────────────────────────────────────────────────
· 필수 컬럼: team1, team2, team1_score, team2_score, team1_prob, team2_prob
· match_id를 안 쓰고 (team1, team2) 이름 쌍으로 매치를 찾음.
  build_match_lookup()이 양방향(정방향+역방향)으로 등록해서
  팀 순서가 CSV에 반대로 적혀 있어도 매칭됨 — 이때 점수도
  자동으로 뒤집어서 비교함 (score_df의 swapped 분기).
· 팀 이름이 매치 목록에 없으면 unmatched로 집계되고 조용히
  채점에서 빠짐. 업로드 시 "팀 이름을 못 찾은 행 N개" 경고로 알려줌.


[ 4 ] 채점 로직 (calc_score)
───────────────────────────────────────────────────────────────
· 10점: 두 팀 스코어 모두 정확
· 6점 : 한 팀 스코어 정확 + 승부 결과도 일치
· 3점 : 한 팀 스코어만 정확 (승부 결과 불일치)
· 1점 : 스코어는 틀렸지만 승부 결과(승/패/무)는 일치
· 0점 : 전부 틀림
· 실제 결과가 무승부면 라벨이 "무승부 + ..." 식으로 바뀜
  (10/6/3/1점 전부 무승부 변형 라벨 있음 — 점수·집계 버킷은 동일,
  라벨만 다름)


[ 5 ] 동순위(동점) 처리
───────────────────────────────────────────────────────────────
· 점수 + 타이브레이커(10점→6점→3점→1점 횟수)가 완전히 같으면
  같은 순위를 줌. 다음 순위는 동점자 수만큼 건너뜀
  (예: 1,1,3,4 — 표준 경쟁 순위 방식. 1,1,2,3 방식 아님)
· 완전히 동일한 CSV를 두 팀으로 제출해서 실제로 공동 순위가
  나오는지 검증함.


[ 6 ] 조별리그 순위 (load_group_standings)
───────────────────────────────────────────────────────────────
· group_stage_result.json에서 stage == "GROUP_STAGE"인 경기만
  필터링해서 계산. (이 파일엔 16강 이후 토너먼트 경기도 같이
  들어있어서 stage 필터링이 꼭 필요함 — 안 거르면 그룹 없는
  경기까지 섞임)
· 정렬: 승점 → 득실차 → 다득점 → 팀명
· 상대 전적, 페어플레이 점수 등 세부 타이브레이커는 의도적으로
  생략함 (4팀 조별리그 규모에서 거의 안 쓰임)


[ 7 ] Streamlit 관련 — 직접 부딪혀서 알게 된 것들
───────────────────────────────────────────────────────────────
※ 이 항목들은 전부 실제로 에러를 내거나 잘못 동작해서 고친 것들임.

· st.cache_data를 load_matches()에 쓰면 안 됨.
  → 함수 코드가 안 바뀌면 매치 데이터 파일이 바뀌어도 캐시를
    안 무효화함. matches.json 갱신 후 KeyError 크래시 원인이었음.
    지금은 캐시 없이 매번 새로 읽음 (파일이 작아서 비용 무시 가능).

· st.iframe(height=0)은 에러를 던짐 (StreamlitInvalidHeightError).
  → 옛 components.html은 height=0을 허용했는데, st.iframe은
    양의 정수/'stretch'/'content'만 허용. height=1로 고침.
    이 버그 때문에 한동안 제출할 때마다 앱이 크래시했었음.

· st.tabs()는 직접 제어 불가능. 다만 st.rerun()을 명시적으로
  호출하면 첫 번째 탭으로 리셋되는 부수효과가 있음.
  → 이걸 역으로 이용해서 "제출 성공 → 메인(리더보드) 탭으로
    이동"을 구현함. 단, 자연스러운 위젯 상호작용(파일 선택 등)
    으로 생기는 rerun은 탭을 안 바꿈 — 직접 부른 st.rerun()만
    탭을 리셋시킴 (Playwright로 직접 확인).

· st.text_input / st.file_uploader는 값이 바뀌는 즉시 매번
  스크립트를 통째로 재실행시킴 (피할 수 없는 기본 동작).
  → st.form으로 감싸서 "제출하기"를 눌러야만 한 번에 재실행되게
    바꿈. websocket 프레임 수로 직접 측정해서 파일 선택/이름
    입력이 0건의 서버 통신을 일으키는 것까지 확인함.

· 스크롤 강제 이동 스크립트(components.html 또는 st.iframe으로
  JS 주입)는 실제 스크롤 컨테이너 셀렉터가 Streamlit 버전마다
  바뀜. 옛 셀렉터 'section.main'은 1.58 버전에 존재하지 않아서
  스크립트가 조용히 실패하고 있었음. 지금은
  '[data-testid="stMain"]' 사용.

· use_container_width는 deprecated. width="stretch" 또는
  width="content"로 교체해야 함 (2025-12-31 이후 제거 예정이라고
  경고 뜸).

· st_autorefresh(streamlit-autorefresh 패키지)로 주기적 자동
  새로고침을 넣었다가 다시 뺐음. 자동 새로고침은 탭을 안 바꾸는
  것까진 확인했지만, 최종적으로는 기능 자체를 안 쓰기로 결정함.


[ 8 ] 배포 환경 — 휘발성 파일시스템
───────────────────────────────────────────────────────────────
· Streamlit Cloud의 컨테이너는 재시작/재배포되면 디스크가
  초기화됨. submissions/ 안의 제출 기록은 git에 커밋하지 않으면
  컨테이너가 죽을 때 같이 날아감.
· 현재 자동 백업/버전관리는 구현 안 함 (Google Sheets API 연동,
  GitHub 자동 커밋 두 가지 방법을 검토했으나 보류 상태).
  필요해지면 사용자_가이드.txt의 버전관리 섹션 참고.
· git push 후 Streamlit Cloud 자동 재배포가 지연되는 경우가
  종종 있었음 → 안 반영되면 "Manage app → Reboot app"으로
  강제 재배포.


[ 9 ] 폴더/파일 정리
───────────────────────────────────────────────────────────────
· test_files/ : 로컬 테스트용 CSV(test_team_A~F.csv). .gitignore에
  등록되어 있어 git에 안 올라감. app.py는 이 파일들을 직접
  참조하지 않음 (example_submission.csv만 참조함).
· db.py, metrics.py, README.md, test_streamlit-main/ : 옛 SQLite
  기반 설계의 잔재. 전부 삭제됨 (사용 안 함).
· 관리자 탭(비밀번호 입력 후 결과 입력)은 제거됨. 지금은
  results.json을 직접 파일로 편집하거나 build_data.py로 재생성.
